# Design Team

Identify the audience, primary task, target screen or artifact and success criteria. For existing work, inspect the relevant route, components, DESIGN.md, tokens and available evidence. A screenshot supports observations about its captured state. Keyboard behavior requires source or interaction evidence.

## Choose the work

- **Plan.** Return the brief, direction, selected skills with their jobs, prerequisites and acceptance checks. Stop there. Keep the plan in the conversation unless the user requested a file.
- **Review.** Inspect the specified flow or diff read-only. Rank findings by effect on the user. Give the location, evidence, impact and suggested change. Distinguish observed usability problems from hypotheses about business outcomes.
- **Build or redesign.** Reuse project content, components, tokens and working interactions. Record the starting behavior before changing an existing flow. Implement through the normal entry point and verify the requested outcome.

Use one source of visual direction. Follow the brief and established brand first. For an unbranded new page consider Hallmark. Use its named redesign workflow on existing work when the user requests Hallmark. Taste Skill can guide a brand-led site when its composition and asset requirements fit. Resolve conflicting advice against the brief, existing system and observed usability. Ask for a decision if competing directions materially change the deliverable and the evidence cannot resolve it.

Read the [catalog](references/catalog.md). Select the smallest set that covers the task. Give each selection a scoped output and a check. Explain a skipped alternative when the choice affects feasibility or scope. For a standalone diagram start with its relationships and requested output format.

Read selected upstream guidance from an available checkout or its pinned link. Check tooling before using native commands. Record whether you applied the method, ran the tool or worked from the catalog alone. Project permissions apply to dependencies, external services, uploads and paid media. When a tool is missing, continue independent work and identify the affected check.

## Verify and hand off

- For changed UI, exercise the primary task on desktop and narrow mobile widths. Check keyboard, focus, error recovery and relevant loading or empty states. For animation, check reduced motion and content access. Use Anti-slop for final UI quality review when available.
- For diagrams, trace relationships and branches against source facts. Inspect label legibility, connector endpoints and clipping at the delivery size. For a 3D model, compare a rendered viewpoint with the supplied reference and test the intended controls.
- Deliver the artifact or findings with methods used, evidence and coverage gaps. Give the route, viewport, interaction or file location behind each material claim. When browser testing is unavailable, distinguish source observations from behavior still awaiting verification.
